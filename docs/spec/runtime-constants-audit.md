Notes on the rows:

- `0x6FAAE3C8` / `0x6FAAE3F0`: the upkeep tax caches. The reader (`0x6F00A3B0`, `0x6F00A4D0`) compares the first cell with `DAT_6FAAE464` (-1.0) and reloads only when they are equal, so -1.0 means "not loaded". The spec (economy.md 2.1) now says so. The code (`crates/sim/src/economy.rs`) uses the built-in defaults, which are the block at 0x6FAAE378..0x6FAAE39C (0.0, 0.3, 0.6 x 8). Consistent.
- `0x6FAB4460`, `0x6FAB4468`: `0x6FAB4468` is the head index of the creep/neutral walk (`((int)x < 1) - 1 & x`, so a value ≤ 0 is an empty list). The start-up value is a negative int. The harnesses (`random_pick_emu.py`, `unit_order_probe.py`) set their own head/link, so their results do not depend on it. Not explained further.
- `0x6FAB7380`: the spec's "agile cursor" (game-loop-2.md) is assumed to start at 0. The start-up value is 299.0. The sim has its own agile clock (`crates/sim/src/timer.rs`) and does not read this address. Needs a dynamic check under Wine before any use.
- `0x6FADB3F8`: pathing-build.md calls it the playable-bounds rect. The start-up dword is the float 32.0 (one cell). The rect source is still open.
- `0x6FAE759C`: the helper `0x6F7E11E0` takes the truncating branch when this flag is nonzero. It is 1 at start-up because `__get_sse2_info` stores its SSE2 result there; the store instruction (`mov [0x6FAE759C], eax`, 0x6F7E1D92) is inside that routine (decompile name `@ 6f7e1d2d`). The round-to-nearest reading in math.md and AGENTS.md was from the file image.

## 6. Open / ambiguous (not changed)

- `0x6FAB7380` start value 299.0 vs the agile-cursor model (section 3 notes).
- `0x6FAE759C` = 1: the float-to-int helper `0x6F7E11E0` has ~180 call sites. Its truncating branch is now the documented run-time path, but no Rust port of that helper exists, and whether a given caller wants truncation or the `fldcw` rounding is still per site (AGENTS 4.3).
- 174 `.data` dwords in `0x90xxxxxx` and two list fields (`0x6FAB4460`, `0x6FAB4468`): values are not floats or image pointers; they are read as signed counters or indices. Not explained; the start-up writer is an initialiser, but its inputs are unknown. Check under Wine.
- `0x6FADB3F8` (32.0): the bounds source of the `war3map.wpm` reader is still open.
- `0x6FA85E1C` and `0x6FA860AC` (decompile-only counters, not mentioned in the repo): `0x6FA85E1C` is incremented at run time (`_DAT_6fa85e1c = _DAT_6fa85e1c + 1`) and starts at 2. Not in the table because the repo does not mention it.
- Reader analysis: the call graph is direct calls only (vtable calls are not followed), so "reachable" is an upper bound. The Ghidra export has 70,512 functions (the earlier note says 70,526; 14 functions are not in the export).
- The softfloat and text harnesses hold every softfloat-spec constant but not FLT_MAX (`0x6FAAE624`); the spec does not show a softfloat function reading it.
